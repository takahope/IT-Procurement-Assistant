# 中央研究院資訊採購合約資安審查助手：v0.2 設計稿

日期：2026-10-15｜狀態：使用者已於本次對話核准為實作計畫基準；正式審查規則仍須逐項核准

本稿承接根目錄 `security-procurement-review-design-spec.md` v0.1.0，將本次對話確認事項及架構評估落實為可規劃的完整描述。原稿保留。本稿不構成個案法律意見或合規認證。

## 1. 已確認需求、設計決定與待決事項

### 1.1 使用者確認

- 採購及簽約主體為臺灣中央研究院；使用者本人為需求負責人、工具規則核准者及最終報告複核者。
- 審查重點是資訊採購合約的資訊安全要求；法規依據含資通安全相關法律與政府採購相關規定。
- 涵蓋資訊服務勞務、雲端服務、套裝軟體、委外開發四種情境；一個案件可以同時涉及多種情境。
- 指定參考資料為 `資訊服務採購契約範本（1131226）.doc` 與 `套裝軟體勞務維護採購作業指南.md`。
- 延續原稿：Word、PDF、掃描混合，約每月一份；重點為一致、不漏項與可追溯，產出逐條結果、理由、引用及修改草稿。
- 真實合約可在本機遮罩並經使用者確認後，送交核准的雲端 AI 服務。此同意不代表特定供應商、地區、留存條件或所有資料類型已獲院方核准。

### 1.2 已隨整體設計核准的設計決定

- 單人、本機執行；Python 明確步驟管線、SQLite 紀錄、JSON 規則及 schema；不採自主工具呼叫、多代理或向量資料庫。
- 提供輕量本機網頁介面，供原文、遮罩、證據與草稿對照；CLI 為維護及評測入口。
- 四類均可建案，但各規則包分別驗收；未驗收的類別明示「尚未支援正式審查」，不默默降級。
- 首版自動擷取支援無追蹤修訂的 DOCX 與文字型 PDF；舊 `.doc`、掃描、複雜版面先經本機轉換及人工確認文字，再送入同一管線。不是承諾所有格式都能自動解析。
- 首版單一核准雲端模型供應商。本地模型及其他供應商保留介面，不列首版完成條件；失敗時可保留資料並轉人工處理。
- 不設獨立語氣模型、案例推薦或自動 Word 寫回；先交付繁中 Markdown 與 JSON 報告及可複製修改草稿。

### 1.3 真實試跑前才需補定的事項

- 特定雲端供應商、模型、地區、資料使用與留存政策、禁止出站資料類別及公司核准依據。
- 院內及單位有效規範、適用系統分級、採購制度確認依據、規則底線與風險分級；使用者對工具規則的核准不替代院內政策核定或法令要求。
- 實際執行設備、核准儲存／備份位置、保存與刪除期限及金鑰管理方式。
- 四類代表合約與完整附件、標註結果、可接受的工時與成本目標。

上述未定事項不阻止使用合成資料及 mock provider 開發；受影響的真實出站及確定結論維持阻塞。

## 2. 目的、成功與非目標

目的：協助承辦人確認合約及其組成文件是否完整承接適用資安要求，識別缺漏、矛盾或削弱要求的文字，提出可查證修改建議。

成功標準：每項範圍內條款及每項適用要求都有結果或未完成原因；結論能回到來源版本與原文；使用者能辨識法令要求、院內要求、範本差異及建議強化；遮罩及複核所花時間計入效益。

非目標：全面法律審查、招標或採購合法性認證、取代院方法定核決權、任意自動寄信或簽署、正式合約覆寫、多租戶服務、微調模型、自動制定政策、保證零漏判或零漏遮。

失敗情形：把未涵蓋當符合、把指南建議當法定底線、檢索漏項卻顯示完整、混用不同版本人工核准、未經確認變更出站目的地，或讓處理一案的人工負擔高於可接受程度卻仍宣稱有效。

## 3. 適用性與來源治理

### 3.1 案件事實

必填或明確標 unknown：採購／簽約單位、經費與採購制度確認紀錄（政府採購、科研採購或其他待確認）、採購法定分類及依據、四類業務標籤、維護／開發／授權／雲端的實際範圍、個資及機敏資料、資料流向與地區、遠端存取、核心系統與防護需求分級、金額與期間、預計簽約／履約日、審查基準日。

中央研究院另有科研採購作業要點，不因主體是中研院即自動判定所有程序規則均適用政府採購法；採購制度由承辦人依有權單位意見確認。業務標籤不能替代採購法定分類。事實未確認只阻擋相關要求，不阻擋其他可查證部分。

### 3.2 四種來源性質

| 性質 | 用途與限制 |
|---|---|
| 適用法令 | 精確條文、有效日期與適用條件；區分機關義務、廠商義務及需落入契約的事項 |
| 院／單位規範 | 院內核定來源與範圍；區分機關應執行事項及需契約化的廠商義務 |
| 指定契約範本 | 比對刪改、選項、待填值及條件；範本差異本身不直接等於違法 |
| 作業指南／建議 | 候選規則及草稿參考；須查證並核准，不因語氣強烈而成為法定要求 |

一項發現可同時有多種依據，報告分別列出。先判適用性，再處理衝突；不能由模型自行以較新、較嚴或文件名稱決定效力。適用法律不被內部核准或案例覆蓋。未知、衝突與無法同時滿足時，呈現差異與待決事項。

工具規則生命週期：`draft -> pending_approval -> active -> superseded / revoked`。新版本不可覆寫舊版本。僅已核准、有效、適用且來源已查核的規則形成確定判斷；法令更新但規則尚未核准時，停用不可靠結論並提出更新提醒，不能解讀為法律義務不存在。

### 3.3 指定文件已知問題與來源擴充

本次以本機文字轉換比對 `.doc`：智慧財產權位於第十六條第三款，資通安全責任位於第十六條第十七款；指南對此所列款次不符，不能直接使用其引用。條次與內容仍需在建立正式規則時逐項對照原檔。

法規資料庫目前列示《資通安全管理法施行細則》115-01-05 修正版，委外監督內容位於第七條；指南與舊範本引用第四條的內容須保留歷史版本並建立新舊對照，不能將舊條號當現行證據。[S1]

院內公開實施要點載有委外契約／RFP、自評與稽核、保密及遠端維護原則等，可列首批候選要求；原則到場與例外遠端的條件均須保留。[S2] 不把院內全部管理要求機械轉成廠商契約義務。

資訊服務範本不能覆蓋所有情境。工程會公開索引目前列有資訊雲端服務及財物採購 1141230 範本；正式規則建立前取得相關全文，核對是否適用、選項與條次，不能只憑下載頁產生條文結論。[S4][S5]

套裝軟體永久授權、訂閱、維護應分辨；不一律要求交付第三方核心原始碼、永久使用權或無上限賠償。SAST、修補期限、通知時限與罰則，須有適用依據或核准立場。指南中的產品名、廠商名、例外與個案條件不得變成通用規則。

## 4. 規則包與全份審查

| 規則包 | 候選範圍，須再查證核准 |
|---|---|
| 共用基線 | 保密、資料目的與權限、事件通知、稽核、複委託、來源授權、退場資料處理 |
| 資訊服務勞務 | 服務範圍、人員、遠端維護、SLA、維護與事件責任、退場 |
| 雲端 | 資料地區、次處理者、租戶隔離、備份復原、可用性、匯出刪除、單方變更 |
| 套裝軟體 | EULA、原廠／代理商授權、修補更新、停止支援、授權到期及可攜性 |
| 委外開發 | 安全開發、檢測、驗收、原始碼與依賴清單、智財授權、部署移交 |

四包可複選並去重；同一規則版本只執行一次。顯示適用／不適用／未知及原因，不能僅靠模型猜分類。

兩條審查路徑必備：

1. 條款路徑：每個可辨識條款均記處理狀態、相關要求及未涵蓋原因。
2. 要求路徑：列舉全部已確認適用要求，逐項找證據；每項產生結論或未完成原因。檢索僅協助找證據，不能決定某條要求是否被執行。

對未確認適用要求也保留待確認紀錄。全文／標籤搜尋先行；20–30 條是初始整理量的建議，不是完整性保證。缺漏只能在所需文件與文字足夠時成立；缺附件或無法完整檢查時改待確認。

主約、需求書、報價、授權／EULA、SLA、資安附件及被引用文件建立清單，含版本、是否取得及效力條款。特別檢查通知、責任限制、資料使用、單方變更與退場等交叉矛盾；未取得引用文件，標示受影響項目。

## 5. 輸入、位置與長文件

原檔保存雜湊；保留原始文字及正規化文字的映射。條款 ID 在同一文件快照內穩定，跨版本透過明確對照，不假設 ID 永遠指同一內容。

DOCX 保留段落、表格路徑、標題及原始編號。其頁碼可能受排版環境影響，未經固定渲染不宣稱可靠頁碼。PDF 使用頁碼及文字區塊／座標。表格巢狀結構、頁首頁尾、文字方塊、修訂、註解、隱藏文字與附件須偵測；不能可靠解析者列出並由人工處理，不靜默略過。

首版不自動接受／拒絕追蹤修訂。舊 DOC、掃描或複雜結構採本機轉換／OCR 輔助，並要求使用者確認審查文字；保留原檔、轉換物及人工修正歷程。數字、否定詞、責任主體、表格錯位是優先校對事項。文件宏、連結及內嵌指令均不執行，不自動下載引用文件。

長文件先建立定義詞、條款層級與交叉引用索引，再按要求／條款分批審查，帶入必要前後文、例外與引用。摘要只能輔助索引，不替代原文證據。上下文不足、截斷、引用迴圈或依賴無法解開時列待確認。分批結果匯總後另查跨條款衝突；所有批次與要求均有完成紀錄，不以模型聲稱「已讀完」計算覆蓋。

## 6. 工作流程與人工關卡

1. 建案：選情境、確認事實、採購制度與審查基準日。
2. 匯入：本機擷取、來源清單與品質報告。
3. 輸入確認：使用者確認文字版本、已知缺件、人工校正及適用性事實。
4. 規則選定：鎖定已核准規則集與來源快照，列未知與未支援範圍。
5. 出站準備：本機遮罩整個請求，預覽實際將送出的資料與目的地。
6. 使用者確認後送出，取得結構化逐項判斷及證據。
7. 本機驗證；必要且有完整覆蓋紀錄時進行跨文件匯總。
8. 對疑慮與缺漏產生修改草稿，驗證數字、定義詞、主體、例外與引用；未知值明示待填。
9. 本機還原並並列原文、依據、理由、未知、草稿，使用者逐項採用／修改／退回。
10. 匯出及封存；只有另行確認的回饋可成為候選案例。

後續草擬／匯總若新增請求內容，也先走出站準備。可一次預覽並核准已完全生成的多個請求；尚未生成的動態請求不得預先視為已核准。

## 7. 遮罩、出站與失敗處理

pii-guard 為候選元件，須固定版本、查依賴授權並以繁中樣本實測。它不是完整出站閘道、機密分級或掃描 OCR 解決方案。[S6] 商業機密與個資分開處理，規則、案例、system prompt、合約文字與錯誤回報都受控。OCR、檢索、embedding 與儲存預設本機。

每案穩定 token 與別名對照，保留甲乙方角色及定義詞；不跨案共用映射，不把映射送模型或寫入一般日誌。原文中本已存在類似 token 的文字要轉義，未知／變造 token 不還原。金額、時限及比例如禁止出站，改本機核算或列待確認，不能過遮後仍猜結論。密碼、API key 與憑證發現即阻擋受影響請求。

`EgressApproval` 綁定實際序列化應用層請求的雜湊、endpoint、供應商／模型、規則與輸入版本及核准人；密鑰認證標頭不在預覽或快照中。核准後內容不可變，送出前核對；傳輸編碼差異可接受，實質請求不得由 SDK 暗加未預覽上下文。供應商回應的工具要求不能觸發任何工具。

同一核准可允許相同目的地、相同內容的有限重送，次數與每次嘗試均記錄並顯示可能重複計費；內容、模型、目的地或參考資料一變就重新準備及核准。格式重試若加入錯誤回覆或新提示，視為新請求。不偷偷換供應商。

遮罩或出站校驗失敗即禁雲端；OCR 不可靠只停受影響結論；引用失敗不補造；還原不完整時保留遮罩稿並標不可直接採用；雲端失敗時保存進度、明示重試或匯出人工檢核資料。不中斷其他可確認工作。

## 8. 輸出與驗證契約

| 結果 | 定義 |
|---|---|
| 符合 | 適用要求有足夠條款證據；不代表整份或實際作業合規 |
| 疑慮 | 具體不符、矛盾或風險未充分處理 |
| 缺漏 | 所需輸入足夠，適用必備要求缺少充分覆蓋 |
| 待確認 | 事實、附件、可靠文字、效力或來源不足／有歧義 |
| 不適用 | 已確認不適用且保存原因 |
| 未涵蓋 | 超出已核准／已驗收的規則範圍 |

風險與結果分開，`critical/high/medium/low/undetermined` 分級由使用者核准。模型自信不作可信度分數，不輸出「整份95%合規」。

每項發現列結論性質（法令／院規／範本差異／建議，可多選）、原文位置、精確來源與版本、推論理由、例外、缺資料、修改目的與連動條款。

三種驗證分欄保存：

- 結構：schema、enum、ID、token 與必填值。
- 來源：短引文確實出現在指定快照，條次可定位、規則有效且來源類型正確。
- 實質：引文是否支持判斷、主體與例外是否被誤讀。機器只能提出檢查結果與疑點，人工實質複核狀態獨立保存；不能用單一 passed 宣稱法律判斷正確。

草稿不得私自新增金額、時限、管轄或責任承諾；保護欄位改變時退回。結構比對不能證明語意完全相同，仍須人工審核。Markdown／JSON 匯出帶案件機敏標示、範圍、未知及版本；本機 UI 對文件及模型內容作純文字／安全渲染，不執行 HTML 或外連。

## 9. 資料模型、版本與核准失效

| 物件 | 最小契約 |
|---|---|
| `SourceReference` | 性質、精確位置、版本、公布／生效日、查核日／人、內容雜湊與存取級別；快照限權保存 |
| `Rule` | ID／不可變版本、來源、要求群組、核准立場與退讓條件、衝突／取代關係、核准人／時間、有效區間與測試 |
| `Requirement` | ID／版本、所屬 Rule 版本、單一可判斷義務、義務主體、適用條件、是否必備、證據要求、確定性檢查與風險；一個 Rule 可含多個 Requirement |
| `DocumentSnapshot` | 原檔與擷取版本／雜湊、文字／位置映射、條款 ID、來源清單及品質／修訂問題 |
| `Review` | 案件、四類標籤與適用性事實、採購制度確認、審查／簽約／履約日、機敏等級、文件快照與確認歷程 |
| `ReviewRun` | 輸入與規則快照、來源／程式／OCR／遮罩／提示／schema 版本、模型 ID、批次狀態、嘗試、延遲、用量及錯誤；不假設重跑逐字一致 |
| `EgressApproval` | 實際出站 artifact、hash、目的地、模型、核准範圍／人／時間、重送限制、作廢原因 |
| `Finding` | run、要求版本、條款 IDs、結果／風險／結論性質、引文、來源、理由、未知、草稿及連動、三層驗證與人工狀態 |
| `CoverageEntry` | 每條款處理狀態、每要求適用性／覆蓋／未完成原因，均綁 run；缺漏無條款時記查核範圍 |
| `Feedback` | 原判、人工正確判斷／理由／採用文字、例外、操作者及時間，新增版本不覆寫 |
| `MaskingSession` | 分案 token、偵測器與手動標記版本、加密映射、出站與還原結果、保存／刪除規則 |
| `AuditEvent` | 人、時間、對象版本、動作、結果及必要雜湊，無原文與密鑰 |

案件狀態：`imported -> needs_input_confirmation -> ready -> reviewing -> draft_ready -> human_review -> approved / needs_revision -> archived`；blocked／failed 是帶恢復點的執行狀態，不代表通過。

輸入、事實、規則或來源實質變更時建立新 run，對舊發現、草稿及人工採用標 stale，歷史核准仍留在原版本但不沿用到新版。單純介面排版變更不影響案件。新 run 可沿用未變的擷取物，不直接沿用舊結論；中斷後保留批次紀錄，避免重複寫入回饋。規則撤銷立即停止受影響出站及確定結論，列出受影響案件；歷史報告保留原快照並標可能過時，不改寫歷史。

## 10. 本機安全、稽核與保存

單人本機程式預設只綁 loopback，採會話憑證、Origin／Host 驗證與變更操作防 CSRF，不開 CORS 通配，不用外部 CDN、字型、分析或遙測。原檔、資料庫、映射、明文及報告位於 repo 外受控目錄，限制目前帳號存取；gitignore 不是權限控制。

SQLite 不假設自帶加密；使用受控磁碟／加密儲存並定義敏感 artifact 加密。API key 與映射金鑰使用 OS keychain 或經核准秘密儲存；不與加密內容一起明文保存。實際金鑰／備份恢復方案須在真實資料啟用前確認並測還原。

一般日誌無原文、prompt、回覆、映射與秘密。為追溯而保存的完整核准請求及實際輸出屬限權案件 artifact，不是一般日誌，依同等機敏性保護與刪除。暫存、OCR 圖片、cache、索引、資料庫 WAL／備份與匯出均列生命週期。留存期限未定，不擅自永久保存，也不刪唯一原檔；真實資料模式在期限政策未確認前不啟用。

程式無寄信、簽署、任意瀏覽或正式合約寫入能力。網路僅允許核准模型 endpoint；下載套件／模型的安裝出站與執行時出站分開。合約與檢索片段永遠是資料，不可改政策、讀別案或觸發工具。文字誘導仍可能影響判斷，須以評測與人工複核處理，不能宣稱工具隔離消除了幻覺。

疑似外洩時停止受影響出站，限權留證、標示服務／時間／範圍與已確認狀態，依核准院內程序處理，不由模型自行宣告法定通報結果。

## 11. 分期與驗收

| 關卡 | 交付與完成條件 |
|---|---|
| M0 規則與標註 | 四類要求清單、原始來源／版本與適用性；核准首批原子要求、風險分級與各類測試樣本。未定要求維持 draft |
| M1 基礎管線 | 文件與人工文字確認、本機遮罩補標、實際 payload 核准、單供應商 adapter、來源／結構校驗、逐條與逐要求報告；可合成資料開發 |
| M2 修改與複核 | 修改草稿、連動與矛盾檢查、保護欄位、人工逐項決定與 Markdown／JSON 匯出 |
| M3 四類驗收 | 各規則包獨立回歸與代表案件人工試跑，明示各類可用範圍；四類均通過才稱首版四類正式支援 |
| 後續 | 自動 OCR、複雜修訂、案例檢索、本地模型與其他供應商、DOCX 匯出，分別評測後納入 |

首版需具備回饋紀錄；自動將案例送入檢索不在首版。後續案例需另核准、綁規則效期、例外及存取範圍；單案接受不等於政策放寬。

測試含符合、疑慮、缺漏、矛盾、例外、缺附件、OCR 關鍵錯字、未勾選／空白選項、套裝授權與維護混合、雲端加客製開發、陳舊法源、文件誘導、token 變造及跨案隔離。按合約／範本家族拆開發與保留集，真實與合成分開；範本參考來源可共用，但案例與答案不得由保留集洩入開發檢索。

必須量測並列分母：擷取錯誤、各類遮罩 precision／recall、完整請求殘留、還原完整率、逐條／逐要求處理覆蓋、各結果 precision／recall、待確認率、高風險漏判、引用可定位與支持率、草稿採用程度、每案人工分鐘與總成本。正式數值由 M0 標註基線後核准，不杜撰準確率或工期。

已知保留測試發布條件：高敏感殘留為零、還原錯換／跨案混用為零、捏造引用為零、高風險判符合為零、未授權出站為零、受保護數值與主體不得無據改動；每項範圍內條款及適用要求均有結果或未完成原因。小樣本只報件數與限制，不能宣稱未來零失誤。另須檢查過多待確認、誤報及人工負擔，不能靠全部棄答通過。

法規／規則／模型／提示／擷取／遮罩變更均重跑相關測試，按規則包比較與回退。合約及使用量增加時先量測人工複核負擔；不預先加入分散式服務。

## 12. 規劃前的評估結論與實作裁量

架構合理、可小規模實作；最大成本為核准規則整理、文件可靠擷取與實質評測，非資料庫或模型呼叫。不能在無代表樣本、設備與供應商資料下承諾固定工期、成本或準確率。

重要原則：四類分包適用、要求全量列舉、跨文件證據、版本與核准失效、完整出站控管。首版應保持明確步驟與低維運負擔。

留給實作者決定：Python 小版本與依賴固定、輕量 UI 框架、schema 函式庫、合法且可靠的解析套件、目錄及模組組織、批次大小與並行度（不超過已核准請求範圍）、退避參數與交易實作。選型先查維護、授權及安全；實測不符合本稿邊界須提出修訂，不可悄悄改需求。安裝、產品程式、專案 scaffolding 及實作計畫須待本稿整體確認後進行。

目前目錄不是 Git 儲存庫；本稿只保存檔案，未建立儲存庫或提交。之後納版控時僅收程式、合成樣本、公開或經核准可納版控的規則與文件；不把內部機敏依據混入公開 repo。
